Run the Pi demo: one agent, every provider, fully governed

Point the Pi coding agent at the gateway and drive Claude, GPT, Gemini, and Cerebras models through one governed endpoint — then flip a model off for a user and watch the very next request get denied.

  1. 1

    Install and wire Pi

    One script installs Pi, adds the gateway as a provider in ~/.pi/agent/models.json, applies the branded theme, and smoke-tests the governed endpoint.

    examples/pi/setup.sh && examples/pi/routes.sh
  2. 2

    Register a demo user

    Creates a fresh non-admin user, issues them a gateway API key from the admin API, and re-points Pi at that identity. Every request Pi makes is now attributed, audited, and priced against that user.

    examples/pi/new-user.sh
  3. 3

    Drive models, then govern them live

    Run pi and hop between Claude, GPT, Gemini, and Cerebras with /model. Then disable a model for the user on Model Selection — their next call to it is denied with a 403, no restart, no new token. Re-enable and it works again. The full script lives in examples/pi/WALKTHROUGH.md.

    pi -p --provider systemprompt --model gpt-oss-120b "hello"
  4. 4

    Inspect the evidence

    Everything the agent did is in the governance spine: Model Selection shows the per-user toggles beside that user’s requests, tokens, and cost; Requests holds the full audit trail — identity, model, provider, policy decisions, denials, latency, and spend for every single call.

    Model Selection Request audit trail
